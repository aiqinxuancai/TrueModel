## 项目来源

本项目的模型归因方法、挑战提示词和默认指纹库源自 **[xqy2006/ModelTrace](https://github.com/xqy2006/ModelTrace)**，感谢原作者的研究与开源贡献。

参考版本：[60949ef](https://github.com/xqy2006/ModelTrace/tree/60949ef522a84f66b1236b459308b48028d36949)。TrueModel 将检测流程移植为 C#，**运行和发布均不依赖 Python**。移植部分与指纹库保留上游 MIT 许可，详见 [来源与许可](THIRD-PARTY-NOTICES.md)。

## 功能

内置默认指纹库为 ModelTrace 提交 `55a2e4a55170423b484d701e9a82ab62b268c811`，包含 16 个模型。启动不会自动升级已有库。在指纹库页面点击“更新默认库”，从 ModelTrace GitHub 下载并校验后原位更新默认库，保留 ID 和启用状态，无需再次切换；已是最新时不作修改，失败时原库保持不变。自定义库不受影响；默认库被删除时会重新创建。

- **分层管理**：站点 → 多个 API Key → 多个模型，密钥加密存储。在站点配置中点击 Key 名称旁的铅笔图标可重命名 Key（1–200 个字符），密钥本身不变，历史记录保留检测时的名称。
- **现代化界面**：卡片式布局、分组侧边导航，支持浅色/深色主题切换（跟随系统并记住选择），适配桌面与移动端。
- **编辑站点**：在“站点配置”点击站点卡片上的“编辑站点”，修改名称和 Base URL，保存后立即刷新。保留站点 ID、启用状态、API Key、模型和历史记录；已提交的归因检测沿用原配置，新提交的检测使用更新后的信息。
- **模型批量管理**：在站点配置中按全部站点、单站点或 Key 筛选、搜索并勾选模型，每次最多删除或替换 500 个模型 ID。支持精确 ID 匹配、区分大小写的文本替换和结果预览；同一 Key 下的重复 ID、空 ID 或正在检测的模型会阻止整批替换。删除会取消所选模型未完成的归因检测；替换后需重新检测，历史记录保留。
- **模型收藏**：在总览的模型状态中收藏或取消收藏，收藏列表显示在模型状态上方，包含相同的检测状态、归因、Juice、糖果、最近检测和操作；刷新页面或重启后仍保留收藏。
- **主页分组折叠**：点击“最近归因正确率 ≥80%”“收藏模型”“模型状态”的标题，可分别展开或收起。默认展开，收起后保留标题和模型数量，搜索筛选随模型状态表一起隐藏；各组状态独立保存在当前浏览器，自动刷新、切换页面及重新打开后仍保留。
- **模型状态排序**：点击“模型状态”表的“最近检测”标题，首次按从新到旧排序，再次点击切换为从旧到新；未检测模型始终置后，相同时间保持原有顺序。点击“站点”标题恢复原有站点 → Key → 模型顺序。搜索、状态筛选及自动刷新保留当前排序，重新打开页面恢复默认顺序。
- **主检测方式切换**：在“设置 → 主要检测方式”选择 ModelTrace（默认）或 HLWY 随机数统计指纹，保存后手动与定时检测均使用所选方式。已排队任务保留提交时的方式、基准、采样次数和反针对设置，历史结果不变。
- **HLWY 检测**：参考 [hlwy-ai-checker](https://github.com/hanlinwenyuan/hlwy-ai-checker/tree/7bddead107da09ddec459522df4b74eb0c7f8ac6)，每次独立请求输出 1–355 的随机数，固定 `temperature=1`、`max_tokens=256`，以众数匹配、余弦相似度和 JS 散度计算匹配度。默认 100 次，可设 40–1000 次，至少 40 个有效样本才能生成报告；连续失败 5 次停止派发新请求，已发出的请求会收尾。单模型采样默认 5 路并发，可设 1–50，与上游一键检测一致；模型之间沿用全局并发模型数限制，最大采样请求并发约为两者乘积，遇到限流可降低采样并发。支持取消及 OpenAI Chat Completions / Anthropic Messages 接口，统计报告采样完成后立即保存并展示，Juice 与糖果随后补充，等待附加检测期间仍占用模型并发名额；取消附加检测保留已生成的统计报告。内置该上游版本的 7 个基准，匹配度不等于身份概率，也不能直接证明降智或掺假。
- **HLWY 反针对模式**：在 HLWY 设置中单独开启（默认关闭）。所有语言已默认添加随机空格和空行；开启后再额外随机插入一个空格，避开首尾和两个数字之间，避免改变数字范围；详情保存当次状态及实际提示词。这是提示词扰动，不保证中转站无法识别检测。
- **HLWY 基准管理**：在“指纹库 → HLWY 基准”点击“从上游更新基准”可立即同步默认基准，也可导入上游 JSON 基准数组或单个对象（需要 355 项分布及 `stats.mode`），保存后优先使用自定义基准；点击“恢复默认基准”或清空并保存可恢复默认。程序启动后自动从上游 `baselines/index.json` 获取文件列表并同步默认基准，每 6 小时检查更新。完整下载并校验后才替换默认基准，缓存保存在数据目录的 `hlwy-default-baselines.json`；网络或数据异常时保留上次缓存，首次离线使用内置基准。同步不覆盖自定义设置或已排队任务的基准快照。对可信来源运行 HLWY 检测后，可从详情导出本次采样为基准。此基准与 ModelTrace 指纹库独立，设置中的 ModelTrace 挑战题目数不作用于 HLWY。来源与 LGPL-2.1 许可见 [第三方声明](THIRD-PARTY-NOTICES.md)。
- **检测与归因**：手动或定时运行，每次 3–6 题可配置；展示模型候选、家族概率和各题耗时。
- **随机多轮封装**：所有题目（ModelTrace 归因、HLWY 每次采样、Juice 各种问法、三次糖果检测及在线指纹采集）都以三条消息发送：`user: 随机问候 → assistant: 随机回复 → user: 真实问题`。每题从中文、英语、日语、韩语、法语、西班牙语、德语、葡萄牙语中随机选择一种语言，再独立选择同语言的问候和回复，共 72 种组合；不额外调用模型生成寒暄，不改动真实题目。同题重试及协议回退复用该次对话，新题重新随机。详情中的题目仍显示真实问题。前置上下文可能影响模型输出，已有指纹库和统计基准不会自动重新校准。
- **题目语言**：在“检测设置 → 通用设置 → 题目语言”独立配置归因及糖果第一、第二、第三题的语言，四项默认中文，均支持中、英、日、韩、法、西、德、葡 8 种语言。归因语言同时用于 ModelTrace、HLWY 和在线指纹采集；三道糖果题可以混用不同语言。所有语言均自动随机插入空格和空行，真实发送的归因/糖果题目随结果保存。手动、定时归因任务及单独糖果刷新在提交时保存语言，之后更改设置不影响已排队任务；历史结果不变，旧版本升级后新增选项默认中文。语言与空白变化可能改变归因分布，已有指纹库和统计基准不会自动重新校准。
- **在线采集指纹**：在“指纹库 → 采集模型指纹”选择已配置的来源模型、基础库、指纹标识和家族，采集 3–6 份有效回答后保存为新版本，可导出或设为当前库。同标识指纹仅在新版本中替换，原库和历史检测不变；失败或取消不保存部分结果。请使用身份可信的来源模型。采集在基础库的特征空间内生成质心，沿用原校准参数，未重新训练或校准扩充后的候选概率。
- **Juice 检测**：仅 GPT（含 ChatGPT、提供商前缀）模型每轮归因题目结束后检测一次，在归因模型右侧、最近检测浮层和详情中显示。参考 [LINUX DO 的多种问法](https://linux.do/t/topic/2457629)，内置 9 条独立文案（XML、算式、中英文直问）；拒答、空回复或非整数时更换文案，取得整数即停止，每条每轮最多尝试一次。按接口地址＋模型＋具体文案持久化尝试次数和正常次数，优先正常率最高的文案；同率优先成功样本多的，再按默认顺序（XML 优先）。网络、鉴权等接口故障停止本轮且不计入文案正常率，取消立即停止。Juice 不再显示“未通过”：未取得有效整数显示“未获取”，接口或响应格式异常显示“错误”。浮窗和详情展示本次题目、回复及具体失败原因（如空回复、拒答、输出截断、内容过滤或 HTTP 错误），保存时隐藏 API Key；自动换问法时展示最后一次尝试，成功后清除失败原因。旧失败记录若未保存原因，会明确提示重新检测。旧记录及不适用模型显示 `—`，未成功显示“未获取”，不影响归因结果。正常仅指可解析为非负整数，数值为模型自报，并非官方预算指标。
- **糖果检测**：每轮检测额外执行三次独立糖果请求：三题可在“检测设置 → 通用设置 → 题目语言”分别选择中文、英语、日语、韩语、法语、西班牙语、德语或葡萄牙语，各自默认中文，保留原题数量、手感辨形和两种配对条件。第二题保留关键词空格、Tab 和换行扰动，第三题保留关键词空格扰动；每道新题均额外随机插入空格和空行，不拆分数字、不删除已有空白，非空白字符不变。同题重试及协议回退复用生成后的题目；详情保存实际发送的题目，旧记录保留原语言。随机空格降低请求重复的概率，但不能保证绕过渠道缓存。三次分别判分，前面的检测接口错误仍继续后续检测，支持单个模型或全部模型单独刷新，在各模型表、最近检测浮层和详情中展示结果、题目与回复。题目与判分规则参考 [haowang02/codex-candy-eval](https://github.com/haowang02/codex-candy-eval/blob/29127fa5a12fb7654e865f684dcaf55ade181349/codex_candy_eval.py)：回复中出现前后非数字的 `21` 即通过，否则未通过；接口异常显示错误，不影响归因结果。沿用上游的文本匹配判分，不分析推理过程是否正确。通过已配置的模型 API 调用，无需本地 Codex CLI；不复现上游 CLI 的上下文。替换原“是/否检测”，旧单测、双测记录保留已有结果，缺少的检测显示未测，重新检测后补齐。
- **糖果用时与分组刷新**：糖果列第一行显示 `通过1(1234) 通过2(2048)`，第二行显示第三测 `通过3(789)`，括号内为各次推理 token；未返回 token 显示 `—`，未运行的检测显示对应编号，例如 `未测3(—)`。每次的题目、回复和独立用时保存并在浮层、详情展示，结果列不显示思考等级。“收藏模型”和“最近归因正确率 ≥80%”分组的 Juice、糖果表头支持刷新本组模型；Juice 仅刷新支持的 GPT 模型，糖果跳过已排队或运行的模型。
- **糖果后台刷新**：单个/全部刷新先写入 SQLite 队列，由后台执行，刷新或关闭页面不会取消任务。页面恢复后显示排队/运行状态，同一模型正在排队或运行时拒绝重复提交；全部刷新自动跳过这些模型。按并发模型数限制糖果刷新并发。程序重启后，未开始的任务继续排队，已运行但未完成的任务显示中断，可手动重新开始。
- **糖果思考等级与用量**：在“检测设置”选择接口默认（初始值）、`none`、`minimal`、`low`、`medium`、`high` 或 `xhigh`，同样作用于三次糖果请求。显式等级通过 OpenAI Chat Completions 的 `reasoning_effort` 发送，需接口和模型支持；失败时不会去掉等级或切换到不支持该参数的协议。仅支持 Anthropic 协议时请选择接口默认。自动检测和单独刷新均保存当次请求等级及 `usage.completion_tokens_details.reasoning_tokens`，模型表在三次状态后分别显示推理 token，浮层与详情标注 `Reason Tok`；未返回用量或旧记录显示 `—`，返回 `0` 则显示 `0`，不以总输出 token 估算。修改设置不改变历史记录，记录的等级是请求值，并非服务端执行等级的证明。字段参考 [OpenAI 官方文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。
- **丹顶鹤骑行检测**：参考 Simon Willison 的 [“鹈鹕骑自行车”SVG 测试](https://simonwillison.net/2024/Oct/25/pelicans-on-a-bicycle/)，将主角改为丹顶鹤，让模型直接生成 SVG，观察鸟类辨识度、车轮和车架结构、肢体与车把及脚踏的空间关系。在模型状态、收藏和最近归因正确率分组的“丹顶鹤骑行”列手动开始，不参与完整和定时归因检测；后台队列持久化，刷新或关闭页面不会中断，服务重启后未开始任务继续执行，运行中的任务标记为中断。列内显示缩略图，点击查看最近 20 次历史、大图、题目、完整回复、展示用 SVG、耗时和推理 token，并可下载 SVG。新一轮失败或排队时仍保留最近成功图的预览。题目语言在“检测设置 → 题目语言 → 丹顶鹤骑行题目语言”独立设置，默认中文，支持中、英、日、韩、法、西、德、葡 8 种语言，入队时保存语言快照，实际题目带随机空白并随记录保存。使用现有 OpenAI / Anthropic 兼容接口，流式请求避免长时间无响应，兼容普通 JSON 返回；无需 Python 或额外图像生成服务。展示前校验 SVG 并移除脚本、事件、外部资源和嵌入网页，原回复以文本保留。“已生成”仅表示取得有效 SVG，不自动判定画面质量、模型身份或是否降智。
- **世界地图检测（内部保留）**：参考 LINUX DO 社区的“仅凭已有地理知识重建世界海陆地图”测试（[新的降智评估方法](https://linux.do/t/topic/2980148)、[重绘世界地图](https://linux.do/t/topic/2987708)）。不参与完整检测和定时检测，已从主列表和题目语言设置中隐藏，内部仍可通过 `POST /api/models/{id}/world-map` 手动开始；任务写入后台队列，刷新或关闭页面不会中断。题目末尾附加交付说明，要求模型在唯一的 ```python 代码块中给出脚本，并在工作目录写出 `world_map_matrix.csv`（可同时写出 PNG）。服务端在临时目录中以清空的环境变量运行脚本（限时 180 秒，模型请求超时 30 分钟；请求使用流式 SSE，避免 Cloudflare 等网关在模型长时间思考时 100 秒无响应返回 HTTP 524，网关不支持流式时自动按普通 JSON 解析），严格校验 90×180 的 0/1 矩阵后，按“白色陆地、黑色水域、最近邻放大”自行生成 180×90 与 1440×720 PNG。原缩略图与历史弹窗代码保留，可通过内部 `openWorldMapHistory(modelId, null)` 查看最近 20 次的大图、陆地占比、脚本、运行输出、题目与完整回复，并下载 PNG、CSV 和脚本；每个模型只保留最近 20 次，超出的记录及本地文件（`<数据目录>/world-maps`）自动删除。题目语言仍可通过设置接口的 `worldMapLanguage` 独立配置（8 种语言，默认中文），题干随机插入空白，交付说明保持原样。Docker 镜像内置 Python 3、numpy 和 Pillow，以 nobody 身份运行脚本，并将数据目录设为仅属主可访问；其他环境需自行安装 Python 3 并加入 PATH（或用 `WorldMap__Python` 指定解释器），找不到时检测直接失败且不请求模型。注意：脚本由模型生成，运行时仍可访问网络；非 Docker 环境下与本程序同权限运行，请仅用于可信渠道。陆地占比仅供参考，不做自动判分。
- **结果通知**：Webhook、PushDeer，支持仅失败通知、测试发送和发送记录。
- **本地运行**：Windows、macOS 单文件自包含版本，启动后自动打开浏览器，SQLite 持久化。
- **容器部署**：Docker Compose、GHCR 镜像，推送版本 tag 自动构建 Release。

> 归因概率是当前指纹库内的候选比较，不能独立证明模型真实身份。超过 3 份有效回答时，沿用 ModelTrace 的 3 查询校准参数。

## 快速开始

### 桌面版

从 GitHub Release 下载并完整解压：

| 平台 | 文件 | 启动方式 |
| --- | --- | --- |
| Windows x64 | `TrueModel-win-x64.zip` | 双击 `TrueModel.exe` |
| macOS Intel | `TrueModel-osx-x64.zip` | 双击 `Start TrueModel.command` |
| macOS Apple Silicon | `TrueModel-osx-arm64.zip` | 双击 `Start TrueModel.command` |

程序为单个自包含可执行文件，内含 .NET 运行时、网页、默认指纹库和 SQLite 原生库，无需安装 .NET 或 Python。首次运行会将内置文件释放到系统缓存目录。压缩包额外附带说明、许可和 macOS 启动脚本；每个压缩包提供 `.sha256` 校验文件。首次启动在网页创建管理员账号；服务仅监听本机，关闭程序即停止服务。macOS 包尚未签名、公证，首次运行可能需要在系统安全设置中允许。

数据保存在用户本地应用数据目录的 `TrueModel` 文件夹（Windows 通常为 `%LOCALAPPDATA%/TrueModel`），启动窗口显示具体路径。升级仅替换程序目录；备份时同时保留数据库和 `keys` 目录。

### Docker

在同一目录创建 `compose.yml` 和 `.env`，使用 GHCR 镜像 `ghcr.io/aiqinxuancai/truemodel` 部署。

**compose.yml**

```yaml
services:
  truemodel:
    image: ghcr.io/aiqinxuancai/truemodel:${TRUEMODEL_VERSION:-latest}
    restart: unless-stopped
    ports:
      - "${HTTP_PORT:-8080}:8080"
    environment:
      ASPNETCORE_HTTP_PORTS: "8080"
      DataDirectory: /data
      Desktop__Enabled: "false"
      Admin__Username: ${ADMIN_USERNAME:-admin}
      Admin__Password: ${ADMIN_PASSWORD:?请在 .env 中设置管理员密码}
    volumes:
      - ./data:/data
```

## 空指纹库

在“指纹库 → 新建空指纹库”填写名称即可创建不含模型条目的库。空库沿用内置库的特征参数，可手动新增指纹，或作为在线采集的基础库；支持导出和重新导入。至少添加两个模型指纹后才能设为当前库。

## 通知设置

在 **通知** 页面配置并保存后，可点击“发送测试通知”验证：

| 通道 | 配置 | 发送内容 |
| --- | --- | --- |
| Webhook | HTTP/HTTPS URL | POST JSON：批次、成功数量、耗时、各模型归因摘要 |
| PushDeer | 推送接口和 PushKey | 支持 [官方服务及自建服务](https://github.com/easychen/pushdeer)，发送结果摘要 |

默认关闭通知；可选择仅失败或取消时发送。URL 与 PushKey 加密保存，留空保留原值，可显式清除。通知不包含 API Key 和模型原始响应；失败不会改变检测结果，在“最近发送记录”查看状态。

Webhook 示例：

```json
{"event":"detection.completed","runId":1,"status":"Completed","durationMs":120000,"total":2,"succeeded":2,"results":[]}
```

## 配置与发布

| 环境变量 | 用途 |
| --- | --- |
| `Admin__Username` / `Admin__Password` | 首次初始化管理员 |
| `DataDirectory` | 指定数据与加密密钥存放目录 |
| `Desktop__Enabled` | 桌面模式：仅本机监听、初始化向导 |
| `Desktop__OpenBrowser` | 是否自动打开浏览器，默认开启 |

检测使用 ModelTrace 的请求格式、有效阈值和重试规则，单次请求超时 240 秒。Web 设置保存每次题目数、调度间隔和并发数。

提交 PR、手动触发或推送 `v*` tag 时，GitHub Actions 运行测试，并分别构建、打包和验证 Windows x64、macOS Intel、macOS Apple Silicon 三个单文件桌面版本。版本 tag 额外创建 GitHub Release，上传压缩包和 SHA-256 校验文件，同时发布 `ghcr.io/<owner>/<repo>:<version>` 和 `latest` 镜像。NuGet 依赖和 Docker 构建使用缓存。

```bash
dotnet test TrueModel.slnx -c Release
```

本地验证 Windows 单文件发行包（PowerShell 7）：

```powershell
dotnet publish TrueModel/TrueModel.csproj -c Release -r win-x64 -p:PublishProfile=Desktop -o artifacts/single-file-app
./scripts/package.ps1 -Rid win-x64
./scripts/smoke-release.ps1 -Rid win-x64
```

macOS 在对应架构的机器上将 RID 替换为 `osx-x64` 或 `osx-arm64`。`Desktop` 发布配置启用自包含单文件和默认桌面模式；环境变量 `Desktop__Enabled` 仍可覆盖桌面模式。

测试包含真实响应的 ModelTrace 归因对照、3/6 题配置、协议回退、管理员鉴权、配置持久化和通知结果；桌面构建额外从压缩包提取单个程序到空目录运行，验证校验和、内置网页和指纹库，以及重启后的管理员、设置、站点、Key 和模型持久化。
